# SambaNAS2 changelog style (source of truth for automation)

This file supplements `.github/CHANGELOG_TEMPLATE.md`. The template describes a
generic `Added/Changed/Fixed` layout with dates; `sambanas2/CHANGELOG.md`
actually uses the emoji layout below with calendar RC versions and no dates.
Automation (and human edits) must follow this file.

## Headings

- Top is always `## Unreleased` (empty when nothing pending).
- Versioned headers are bare RC/release versions, no date:
  `## 2026.9.0-rc15`, `## 2026.9.0`, `## 2026.9.0-beta.42`. Never append dates.
- `config.yaml:version` (C) is source of truth. Rules:
  - `C == H` (first `##` != `Unreleased`): append to `## Unreleased` only (Us1/Us4).
  - `C` not in file + `Unreleased` non-empty: promote `Unreleased → ## C`,
    leave a new empty `## Unreleased` on top (Us2/Us3).
  - `C` already in older `##`: do not duplicate, only ensure `## Unreleased` exists.
  - `mergerelease/*`, `beta`, `prerelease/*` never contain `## Unreleased`
    (S2 = S1 minus the `Unreleased` line).

## Sections (only when non-empty)

- In the first versioned release (first `##` that is not `## Unreleased`),
  `### 🙏 Thanks` is always first and `### 🚨 Notes` always second,
  regardless of edit order. A deterministic normalization step re-sorts them.
- Remaining sections keep this order after Thanks/Notes:
  `### ✨ Features`, `### 🐛 Bug Fixes`, `### 🏗 Chore`,
  `### 💥 Breaking Changes`, `### 🔄 Migration Notes`.
- `### 🙏 Thanks`: keep short, release entries only (never in `## Unreleased`).
- `## Unreleased` itself needs no Thanks/Notes; use Features/Fixes/Chore only.

## SRAT entries (no dedicated section)

- There is NO `### 🐭 Features from SRAT` section. Historical `🐭` blocks in old
  releases stay untouched; new releases never add one.
- The used SRAT version is referenced once in `### 🏗 Chore`, with a link to
  the full upstream changelog, e.g.:
  `- Update SRAT to [v2026.9.0-rc15](https://github.com/dianlight/srat/blob/2026.9.0-rc15/CHANGELOG.md)`
- Only important user-facing SRAT changes are reported, inside the normal
  `### ✨ Features` / `### 🐛 Bug Fixes` sections, each suffixed with the
  source, e.g.: `- Interface IP resolution at config generation time (from SRAT v2026.9.0-rc15)`.
- Selection and wording is done by the AI changelog action: read
  `Dockerfile ARG SRAT_VERSION`, fetch that tag's `CHANGELOG.md` from
  `https://raw.githubusercontent.com/dianlight/srat/<ver>/CHANGELOG.md`,
  keep breaking/user-visible features and fixes, drop internal churn,
  Thanks/Roadmap noise and duplicates of add-on bullets.
